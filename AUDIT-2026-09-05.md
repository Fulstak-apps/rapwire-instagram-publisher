# RapWire reliability audit

Reviewed publisher state handling, workflow ordering, local runner, collector lock,
watchdog, caption/topic logic and regression tests. This is a code/log audit;
live delivery with replacement credentials has not been verified.

## Fixed
- Watchdog no longer counts the same health snapshot as repeated failures or
  pauses an entire item because one platform failed. It no longer writes queue
  records concurrently with the collector.
- Watchdog uses the supplied clock for retry eligibility and excludes uncertain
  publish requests from redispatch candidates.
- Workflow summaries expose the recorded Instagram block reason, rather than
  describing every block as exhausted capacity.
- Removed duplicate Node setup from each publishing run.
- Threads engagement and growth checks can proceed after publisher failure,
  provided prior publication-state reconciliation succeeded.

## Remaining operational findings
- Latest checked-in health snapshot reports Meta code 190: invalidated Instagram
  session. Replace the authorized Instagram credential; do not bypass quota gates.
- Snapshot lists 106 pending Stories and numerous legacy videos lacking validated
  crop/hash evidence. Recapture those assets before publishing; no safety gates
  were disabled to clear the backlog.
- Local newsroom mkdir lock can survive a crash; collector stale-lock acquisition
  also has a race window. A shared tested owner-aware lock implementation is a
  follow-up, not safe to hot-swap while a collector is running.
- GitHub scheduling is not an exact delivery clock. Keep resumable containers,
  account-wide pacing and uncertain-publish reconciliation intact.
- Full audit is not a guarantee of no remaining defects. No existing posts were
  altered, deleted or republished by this audit.

## Verification
171 Node tests and 18 Python tests pass after these changes. No live publish was
forced during testing. Facebook remains disabled; no Codex recurring job added.
